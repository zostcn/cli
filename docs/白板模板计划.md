# 白板模板(`template-bare/`)实施计划

> **状态:已立项、未实施**(2026-10-14 拍板)。
> 只记录方案,不动工;实施从 §3 开始,若与现实冲突,先改本计划再动手。
>
> 归属:`zostcn/cli` 仓库 —— 新增独立模板目录 `template-bare/`,
> 脚手架加 `create <项目名> --bare`;现有 `create`(全量模板)行为**完全不变**。

---

## 0. 已拍板的决策(2026-10-14)

| # | 议题 | 结论 | 影响 |
|---|---|---|---|
| 1 | 目标形态 | **空白页基线**:只有工具链和骨架,无登录、无接口层;给官网这类项目当起点 | 不是「全量模板删登录」,是独立的最小模板 |
| 2 | 落地方式 | **独立 `template-bare/` 目录**,不用「同模板生成时剥离」 | 白板与全量差异几乎是两个项目,剥离清单覆盖 ~90% 模板、规则与模板必须永远同步,太脆 |
| 3 | 部署流水线 | **保留** `deploy/` + `.github/workflows/deploy.yml`(生成即可推) | 官网终归要上线;占位符规则两模板天然一致,脚手架校验不分叉 |
| 4 | 命令形态 | **`create <项目名> --bare`**,默认(无 flag)仍是全量模板 | 老用法语义不变;USAGE 加一行 |
| 5 | 后端依赖 | 白板**完全不连后端**:无 axios、无 `/api` 代理、无 nginx `/api` 反代、无 `VITE_API_BASE_URL` | 以后要调公开接口的项目,参照全量模板自行补 |

**为什么独立目录而不是生成时剥离**(决策 2 的理由,防止以后翻案重问):
剥离方案的「排除清单 + 改写规则」几乎覆盖整个模板,等于用规则维护一份隐形副本;
规则和模板必须逐字同步,漏一条就生成半登录半空白的残次品。独立目录各自演进,
占位符替换规则(包名 / title / base / nginx / workflow)**本来就与 src 无关**,
两模板共用一份 `rulesFor`,靠 smoke 双跑兜底,维护成本只在工具链配置的少数几处
(vite.config / eslint / .gitignore / workflow),漂移在 `npm test` 就会红。

## 1. 目标与非目标

**目标**

1. `zost-cli create my-site --bare` 生成可直接开发的白板项目:
   Vite + Vue3 + TS + Tailwind + ESLint + Prettier + Vitest,
   静态路由(Home + 404)、设计 token(`src/theme/tokens.css`)、主题预置脚本、部署流水线。
2. 不带任何认证/接口层:无 pinia、无 axios/vue-query、无 orval、无守卫/角色/权限指令、
   无 Login/Register/Settings/Devices 页面、无后台布局壳。
3. 全量模板(`template/`)一行不改;`create` 不带 flag 的行为、smoke 现有用例语义不变。
4. 占位符替换规则一份共用:两模板的 `package.json` name、`index.html` title、
   vite `base: "/",`、两份 nginx conf 的 `<项目名>`、workflow 的 `PROJECT` 逐字同构。

**非目标(本期不做)**

- 不做共享组件库 / 生成后回灌(边界照旧:模板改动不回灌已生成项目)。
- 不改现有 `template/`,不给它加任何开关。
- 不做交互式「要登录吗」问答 —— 只有 flag。

## 3. 脚手架与仓库机制改动

### 3.1 `src/scaffold.ts`

- 引入变体:`type Variant = "full" | "bare"`;`TEMPLATE_DIRS: Record<Variant, string>`(`../template/`、`../template-bare/`)。
- `scaffold(projectName, targetDir, opts?: { variant?: Variant })`,默认 `full`。
- `rulesFor(projectName)` **不分叉** —— 两模板占位标记逐字同构(这是独立目录方案的前提,smoke 双跑校验)。
- `README_INTROS: Record<Variant, string[]>`:替换 README 开头的逐字标记按变体取(bare 的第 3 行指 `template-bare/` 并提 `--bare`,见 §4)。
- `DOTFILE_FALLBACK` 改成按变体:`.npmrc` 两变体同文,`.gitignore` 不同(白板无 orval 行)。**导出形状变了,smoke 同步改**。
- 同步失败的报错文案不变(「脚手架与模板不同步」仍是唯一出口)。

### 3.2 `src/index.ts`

- 解析 `--bare`(位置任意:`create my-app --bare` / `create --bare my-app`);未知 `--flag` 报错。
- USAGE 加一行:`--bare  从 template-bare/ 生成白板项目(无登录/接口层,官网用)`。
- 交互问答(只有项目名)不变;生成后的「下一步」提示不变。

### 3.3 仓库其余

- `package.json`:`files` 加 `"template-bare"`(registry 包必须带上它);description 提两个模板。
- `scripts/smoke.mjs`:
  1. 点文件兜底断言按变体循环(`DOTFILE_FALLBACK[variant]` ↔ 各自模板目录逐字相等);
  2. 新增 bare 用例:`create demo-bare --bare` 成功 → 断言占位替换(name/title/base/nginx/workflow/README 全套)+ 断言 `src/api`、`orval.config.ts`、`src/pages/LoginPage.vue` **不存在** + `deploy/nginx.conf`、`.github/workflows/deploy.yml` **存在**;
  3. registry 路径(pnpm pack 那段)补一次 `create packed-bare --bare`,关键文件在、`node_modules` 不进。
- 仓库 `README.md`:目录树加 `template-bare/`、用法加 `--bare`、兜底常量说明改成「与**各自**模板逐字一致」。
